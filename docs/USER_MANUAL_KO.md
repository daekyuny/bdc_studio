## 개요

Burndown Studio는 애자일 팀을 위한 웹 기반 스프린트 번다운 트래커입니다. 다팀·다그룹 조직을 지원하며, 역할 기반 접근 제어, 실시간 차트 시각화, 백로그 관리, Firebase 기반 클라우드 동기화 기능을 제공합니다.

---

## 역할 및 조직 구조

| 역할 | 설명 |
|---|---|
| **멤버 (Member)** | 팀 구성원. 태스크를 업데이트하고 스프린트를 조회하며 작업을 기록합니다. |
| **프로덕트 매니저 (PM)** | 그룹을 소유합니다. 팀을 생성·관리하고, 멤버를 초대하며, 스프린트를 만듭니다. |
| **슈퍼 매니저 (SM)** | 시스템 관리자. 모든 사용자, 그룹, PM 요청에 대한 전체 권한을 가집니다. |

**조직 계층 구조:**

```
그룹 (PM 소유)
└── 팀 (그룹당 여러 개)
    └── 스프린트 (팀당 여러 개)
        └── 태스크 (백로그에서 연결)
```

## 로그인

### 이메일 / 비밀번호
이메일과 비밀번호를 입력한 후 **로그인** 버튼을 클릭하거나 Enter를 누릅니다.

### Google 로그인
**Google로 로그인** 버튼을 클릭하면 Google 계정 선택 화면이 열립니다. 이미 등록된 이메일과 자동으로 연결됩니다.

### PM 계정 요청
직접 그룹을 생성하고 관리하려면:

1. 랜딩 페이지에서 **PM 계정 요청**을 클릭합니다.
2. 이름, 이메일, 원하는 그룹 이름, 소속 기관/설명(선택)을 입력합니다.
3. 제출하면 슈퍼 매니저가 승인 또는 거절합니다.
4. 승인 시 계정 등록 링크가 이메일로 전송됩니다.

> **참고:** SM은 필요 시 관리자 화면에서 PM 계정 요청 기능을 비활성화할 수 있습니다.

## 팀 선택 화면

로그인 후 팀 선택 화면으로 이동합니다.

- **팀 카드**에는 팀 이름과 멤버 아바타가 표시됩니다. 카드를 클릭하면 해당 팀의 스프린트 뷰로 진입합니다.
- **PM 전용**: **새 팀** 카드로 추가 팀을 생성할 수 있으며, 각 카드의 **관리** 버튼으로 멤버 관리 모달을 열 수 있습니다.
- **팀 소유자**: 소유한 팀에 **이름 변경** 및 **삭제** 버튼이 표시됩니다.
- **PM 전용**: 팀 카드를 드래그하여 순서를 바꿀 수 있습니다.
- 멤버 아바타를 클릭하면 전체 프로필 사진을 볼 수 있습니다.
- 헤더의 이름/아바타를 클릭하면 **프로필 편집** 모달이 열립니다.

## 스프린트 뷰

메인 작업 공간입니다. 모든 스프린트 추적, 태스크 관리, 차트 시각화가 여기서 이루어집니다.

### 스프린트 사이드바

왼쪽 패널에 모든 스프린트가 순서대로 나열됩니다. 스프린트를 클릭하면 해당 스프린트가 활성화됩니다.

### 헤더 및 툴바

**프로젝트 오늘(TODAY) 선택기**
가장 중요한 컨트롤입니다. 모든 태스크 업데이트의 기준 날짜를 설정합니다 — 프로젝트 내에서 "오늘이 몇 월 며칠인가"를 의미합니다.

- TODAY 날짜를 클릭하면 날짜 선택기가 열립니다. 근무일만 선택 가능합니다.
- 페이지를 다시 로드할 때마다 실제 시스템 날짜로 초기화됩니다.
- 모든 태스크 업데이트(작업량/잔여량)는 이 날짜로 기록됩니다.

**스프린트 액션 버튼 (우측 상단):**

| 버튼 | 동작 |
|---|---|
| 스프린트 추가 | 새 스프린트를 생성합니다 (기본값: 14일, 개발자 4명, 효율 0.8). 계획 모달이 바로 열립니다. |
| 스프린트 편집 | 스프린트 편집기를 엽니다 (날짜, 개발자 수, 효율, 설명). |
| 스프린트 초기화 | 모든 진행 기록과 태스크 로그를 초기화합니다. 태스크는 유지되며 브라우즈 날짜가 초기화됩니다. |
| 스프린트 삭제 | 활성 스프린트와 모든 데이터를 영구 삭제합니다. |
| 가져오기 | 이전에 내보낸 JSON 파일을 업로드하여 스프린트 데이터를 복원하거나 병합합니다. |
| 내보내기 | 모든 스프린트·백로그·환경설정을 JSON 백업 파일로 다운로드합니다. |

### 통계 카드

헤더 아래, 차트 위에 표시됩니다. 실시간으로 업데이트됩니다.

| 항목 | 의미 |
|---|---|
| 기간 | 스프린트 시작·종료 날짜 및 일수 |
| 근무일 | 공휴일을 제외한 평일 수 |
| 총 포인트 | 스프린트 태스크 추정치의 합계 |
| 잔여 | 현재 `remain` 값의 합계 |
| 완료 태스크 | 상태가 "Done"인 태스크 수 |
| 가용 일수 | `개발자 수 × 근무일 × 효율` (팀 전체 용량) |
| 진행률 | `(총 포인트 − 잔여) / 총 포인트` (진행 바 포함) |

### 번다운 차트

세 개의 선으로 구성된 SVG 차트입니다.

| 선 | 색상 | 의미 |
|---|---|---|
| 이상선 (Ideal) | 파란 점선 | 근무일 동안 총 포인트에서 0까지 선형 감소 |
| 실제선 (Actual) | 빨간 실선 | 일별 태스크 로그 기준 실제 잔여 포인트 |
| 범위선 (Scope) | 회색 | 시간 경과에 따른 계획 총량 (태스크 추가/제거 시 변동) |

**인터랙션:**

- **X축 날짜 레이블 클릭**: **브라우즈 날짜**를 설정하면 태스크 테이블이 해당 날짜의 과거 상태로 전환됩니다. 같은 날짜를 다시 클릭하면 초기화됩니다.
- **일수 표시** 체크박스: 날짜 레이블 아래에 스프린트 일차(1, 2, 3…)를 추가로 표시합니다.

**범위 감소(Scope Drop)** 는 계획된 태스크가 제거될 때 차트에 마커로 표시됩니다. 같은 태스크를 다시 추가하면 범위 감소가 취소됩니다.

### 태스크 테이블

활성 스프린트의 모든 태스크를 나열합니다.

**컬럼:**

| 컬럼 | 설명 |
|---|---|
| ID | 태스크 식별자 (예: `0.1.2`) |
| 태스크 | 태스크 이름. 마우스를 올리면 연결된 백로그 스토리가 표시됩니다. |
| 실제/추정 | `작업량 + 잔여량 / 추정` |
| 작업량 | 작업한 시간/일 — 업데이트 모드에서 편집 가능 |
| 잔여량 | 남은 시간/일 — 업데이트 모드에서 편집 가능 |
| 상태 | 자동 설정: Todo / In Progress / Done |
| 완료일 | 잔여량이 0이 될 때 자동 기록 |
| 액션 | 업데이트, 제거, 이동, 분할 (상황에 따라 표시) |

**진행 기록:**

1. 태스크 행의 **업데이트**를 클릭합니다.
2. 담당자가 없는 경우 팀원 중에서 선택하는 프롬프트가 표시됩니다.
3. **작업량**과 **잔여량** 값을 입력합니다.
4. Enter를 누르거나 **저장**을 클릭합니다.

상태는 자동으로 변경됩니다:
- `잔여량 = 0` → **Done** (완료일 기록)
- `작업량 > 0, 잔여량 > 0` → **In Progress**
- `작업량 = 0` → **Todo**

**태스크 제거:**
- 활성 스프린트에서 **Todo** 상태의 태스크에 표시됩니다 (마지막 날 제외).
- 태스크를 백로그로 되돌립니다. 원래 계획된 태스크였다면 **범위 감소** 기록이 생성됩니다.

**마지막 날 액션** (스프린트 종료일에만 표시):

| 버튼 | 동작 |
|---|---|
| 이동 | 다른 스프린트로 태스크를 이동합니다 (현재 스프린트에 범위 감소 생성) |
| 분할 | 현재 태스크를 Done 처리하고 잔여 작업을 다른 스프린트에 새 태스크로 복사합니다 |

**정렬 및 순서 변경:**
- 컬럼 헤더를 클릭하면 오름차순/내림차순으로 정렬됩니다.
- 정렬되지 않은 상태에서 ⠿ 핸들을 드래그하여 행 순서를 수동으로 변경할 수 있습니다.

**과거 조회:**
브라우즈 날짜가 설정된 경우(차트 클릭) 태스크 테이블은 해당 날짜 기준의 태스크 상태를 보여줍니다. 아직 존재하지 않던 행은 흐리게 표시됩니다.

### 백로그 패널

태스크 테이블 아래에 접을 수 있는 패널로, 현재 스프린트에 포함되지 않은 백로그 태스크를 표시합니다.

- **행을 드래그**하여 태스크 테이블로 끌어다 놓으면 스프린트에 추가됩니다.
- **ID로 추가**: 태스크 ID(예: `0.1.1`)를 입력하고 **추가**를 클릭하거나 Enter를 누릅니다.

### 환경설정

**⚙** (설정) 버튼을 클릭하면 환경설정 모달이 열립니다.

**커스텀 공휴일**
근무일 계산에서 제외할 날짜를 추가합니다 (예: 회사 휴일). 날짜와 레이블을 입력하고 추가를 클릭합니다.

**주말 근무일**
스프린트 기간 중 근무일로 지정할 특정 토요일이나 일요일을 설정합니다.

**멤버**
팀 멤버 목록 (읽기 전용). 멤버를 클릭하면 프로필을 볼 수 있습니다.

**나의 메모 (비공개)**
본인만 볼 수 있는 개인 마크다운 메모입니다. `**굵게**`, `*기울임*`, `` `코드` ``, `# 제목`, `- 목록` 문법을 지원하며, 입력 후 800ms가 지나면 자동 저장됩니다.

## 백로그 탭

백로그는 **스토리 → 태스크** 구조로 구성된 마스터 태스크 저장소입니다.

### 구조

- **스토리**: ID(예: `0.1`), 설명, 우선순위를 가진 사용자 스토리.
- **태스크**: 스토리 하위 항목으로 ID는 `스토리ID.N` 형식(예: `0.1.2`), 설명, 추정치(일), 담당자 목록을 가집니다.

### 스토리 조작

| 동작 | 방법 |
|---|---|
| 스토리 추가 | **스토리 추가** 클릭 |
| 스토리 편집 | 스토리 행의 **편집** 클릭 |
| 스토리 삭제 | 편집 모드에서 **삭제** 클릭 (하위 태스크 전체 삭제) |
| 펼치기/접기 | 스토리 행의 ▼/▶ 토글 클릭 |
| 전체 펼치기 / 전체 접기 | 테이블 위의 버튼 클릭 |

### 태스크 조작

| 동작 | 방법 |
|---|---|
| 태스크 추가 | 스토리의 **태스크 추가** 클릭 (편집 모드) |
| 태스크 편집 | 태스크 행의 **편집** 클릭 |
| 태스크 삭제 | 편집 모드에서 **삭제** 클릭 |
| 담당자 지정 | 담당자 필드 클릭 → 팀원 체크박스 선택 |

### 가져오기 / 내보내기

- **엑셀에서 가져오기**: Story ID, User Stories, Priority, Task ID, Description, Est. Days, Assigned To 컬럼이 있는 `.xlsx`/`.xls` 파일을 업로드합니다.
- **엑셀로 내보내기**: 현재 백로그를 서식이 적용된 `.xlsx` 파일로 다운로드합니다.
- **전체 삭제**: 전체 백로그를 삭제합니다 (확인 프롬프트 표시).

## 그룹 및 팀 관리 (PM)

### 그룹 생성 (최초 로그인)

새로 승인된 PM이 처음 로그인하면 그룹 생성을 안내받습니다. 이미 PM 소유인 팀이 있다면 새 그룹에 자동으로 연결됩니다.

### 그룹 화면

그룹을 생성했거나 기존 그룹이 있는 경우 접속됩니다. 두 섹션으로 구성됩니다:

**팀**
- 카드를 드래그하여 순서를 변경합니다.
- **멤버 관리** 버튼으로 해당 팀의 멤버 관리 모달을 엽니다.
- **이름 변경** 버튼으로 팀 이름을 수정합니다 (소유자 전용).
- **삭제** 버튼으로 팀을 제거합니다 (소유자 전용).
- **새 팀** 카드로 추가 팀을 생성합니다.

**멤버**
그룹 내 모든 멤버의 이름, 이메일, 역할, 전화번호를 표시합니다.

### 멤버 관리 모달

**현재 멤버 (왼쪽 패널)**
- 기존 팀 멤버를 표시합니다.
- **제거** 버튼 — 미완료 태스크 담당자인 경우 비활성화됩니다 (해당 태스크 표시).

**멤버 추가 및 초대 (오른쪽 패널)**

| 방법 | 사용 상황 |
|---|---|
| 그룹에서 추가 | 이미 그룹에 속한 멤버 — **추가**를 클릭하여 이 팀에 포함시킵니다. |
| 이메일로 초대 | 이메일 주소를 하나 이상 입력하면 초대 링크가 발송됩니다. 수신자가 링크를 클릭하여 등록하고 팀에 합류합니다. |
| 사전 등록 | 아직 가입하지 않은 Google 계정 소유자를 위한 방법. 최초 Google 로그인 시 자동으로 팀에 합류합니다. |

대기 중인 초대와 사전 등록 항목은 **취소** 버튼과 함께 목록에 표시됩니다.

### 프로필 편집

이름 또는 아바타를 클릭하여 접근합니다. 다음 항목을 수정할 수 있습니다:
- **표시 이름** 및 **전화번호**
- **아바타 사진** — 이미지를 자르고 업로드합니다 (최대 5 MB). 삭제하면 이니셜로 표시됩니다.
- **비밀번호** (Google 계정이 아닌 경우만) — 변경하려면 현재 비밀번호가 필요합니다.

## 관리자 화면 (SM)

슈퍼 매니저만 접근할 수 있습니다.

### 사용자 탭

| 컬럼 | 설명 |
|---|---|
| 이메일 | 사용자 이메일 |
| 이름 | 표시 이름 |
| 역할 | 드롭다운 — Member / PM / SM으로 변경 |
| 그룹 | 드롭다운 — 사용자를 그룹에 배정 |
| 삭제 | 사용자 삭제 (SM은 비활성화) |

컬럼 헤더를 클릭하면 정렬됩니다.

### 그룹 탭

모든 그룹의 이름, 소유자, 멤버 수, 팀 수를 보여주는 읽기 전용 테이블입니다.

### PM 요청 탭

- **PM 요청 비활성화** 토글 — 체크 시 랜딩 페이지에서 "PM 계정 요청" 버튼이 숨겨집니다.
- **요청 테이블**: 모든 PM 계정 요청과 상태(대기 중 / 승인됨 / 거절됨)를 표시합니다.
  - **승인** — PM Firebase 계정을 생성하고 로그인 링크가 담긴 등록 이메일을 발송합니다.
  - **거절** — 요청을 거절 상태로 표시합니다.
  - **삭제** — 요청 레코드를 완전히 삭제합니다.

## 주요 워크플로우

### 새 스프린트 계획

1. **스프린트 추가** 클릭 → 날짜, 개발자 수, 효율 설정 → **저장 및 태스크 추가**.
2. 스프린트 계획 모달에서 백로그 태스크를 스프린트로 드래그합니다.
3. **완료** 클릭 — 계획된 포인트가 이상선(Ideal Burndown) 기준으로 고정됩니다.

### 일일 진행 기록

1. 매 근무일 프로젝트 TODAY가 시스템 날짜로 자동 초기화됩니다.
2. 각 팀원이 담당 태스크의 **업데이트**를 클릭하고 작업량과 잔여량을 입력한 후 저장합니다.
3. 번다운 차트가 실시간으로 업데이트됩니다.

### 스프린트 중간 범위 변경 처리

| 상황 | 조치 |
|---|---|
| 스프린트 중간에 태스크 추가 | 백로그 패널에서 드래그하거나 ID로 추가. `addedDate`가 오늘로 설정됩니다. |
| Todo 태스크 제거 | 제거 클릭. 차트에 범위 감소 마커가 생성됩니다. |
| 태스크 이연 (마지막 날) | 이동 클릭 → 대상 스프린트 선택 |
| 태스크 분할 (마지막 날) | 분할 클릭 → 현재 태스크 완료 처리, 잔여 작업이 다음 스프린트에 새 태스크로 복사됩니다. |

### 과거 진행 상황 조회

1. 번다운 차트의 날짜 레이블을 클릭하여 브라우즈 날짜를 설정합니다.
2. 태스크 테이블이 해당 날짜 기준 상태로 표시됩니다.
3. 같은 날짜를 다시 클릭하면 오늘로 돌아옵니다.

### 새 팀원 초대 (PM)

1. 팀 선택 화면 → 대상 팀의 **관리** 클릭.
2. 오른쪽 패널 → **이메일로 초대** → 이메일 주소 입력 → **초대 발송**.
3. 수신자가 이메일 링크를 통해 등록을 완료합니다.
4. Google 계정 소유자의 경우 **사전 등록**을 사용하면 최초 로그인 시 자동으로 팀에 합류합니다.

### PM 요청 승인 (SM)

1. 슈퍼 매니저로 로그인합니다.
2. 관리자 화면 → **PM 요청** 탭.
3. 대기 중인 요청의 **승인**을 클릭하면 사용자에게 등록 링크가 발송됩니다.

## 데이터 및 동기화

### 로컬 스토리지
모든 앱 상태는 `localStorage`의 `burndown-studio` 키에 저장됩니다. 오프라인에서도 작동하며 페이지 새로고침 후에도 유지됩니다.

### Firebase 클라우드 동기화
Firebase가 설정된 경우 상태가 Firestore에 실시간으로 추가 동기화됩니다. 같은 팀의 여러 사용자가 실시간 업데이트를 공유합니다. 빠른 연속 편집을 묶어 처리하기 위해 저장은 500ms 디바운스됩니다. 자신이 방금 저장한 데이터를 다시 불러오지 않도록 5초간 에코 억제가 적용됩니다.

### 가져오기 / 내보내기 (JSON)

- **내보내기**: 모든 스프린트, 백로그, 환경설정을 JSON 파일로 다운로드합니다 — 전체 백업에 유용합니다.
- **가져오기**: 이전에 내보낸 파일을 업로드합니다. **병합** (기존 데이터에 추가) 또는 **전체 교체** 중 선택합니다. 백로그에 더 이상 존재하지 않는 스프린트 태스크(고아 태스크)는 가져오기 완료 전에 표시됩니다.
